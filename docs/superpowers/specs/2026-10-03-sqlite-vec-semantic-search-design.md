# sqlite-vec 可选语义检索

用户选择 sqlite-vec，并明确选择独立 Embedding API、单独配置地址和密钥。本次延续已授权的可选检索实现，保留 Windows 原生界面、即时本地检索和低频写入约束。

## 产品范围

默认关闭。增加独立“语义检索设置”：启用、API 地址、模型 ID、密码形式的 API Key、清除密钥和索引范围。范围默认“固定内容与收藏”，可改为“全部文本”。设置中明确说明：建立索引将把选定范围的文本发送给 Embedding 服务，语义查找发送本次查询；不上传图片、HTML/RTF 二进制格式或文档文件正文。文档和文件夹只索引已保存的名称、路径、别名和标签；文本剪贴板索引文字，每条参与向量化的输入最多 4096 字符。无文本的图片条目不索引。

普通输入继续即时搜索关键词、拼音、功能。启用后提供“语义查找”按钮，点击才请求查询向量；关键词结果在网络期间仍可使用。设置菜单和功能检索提供“语义检索设置”“建立/更新语义索引”和运行期间“取消索引”；用户主动启动建立/更新索引，不在每次复制、每次输入或启动程序时自动请求服务。不新增全局快捷键，不自动执行模型建议，不引入文档解析、RAG 回答或 MCP。

## API 和任务边界

使用 OpenAI 兼容 Embeddings 协议：POST 到 `/v1/embeddings`，Bearer Key，JSON 为 `model`、字符串数组 `input`、`encoding_format: "float"`，不假设服务支持缩减维度。地址接受根地址、`/v1`、完整 `/v1/embeddings` 及代理前缀；参数校验沿用现有地址规则。模型 ID 用户填写。DPAPI 使用现有当前 Windows 用户的密钥保护，Embedding 与 Claude 的密钥独立。

一次索引请求最多 16 条，输入最多 4096 字符/条，请求体最多 512 KiB；响应体最多 2 MiB；向量维度 1..=4096，所有坐标必须是有限 f32，向量不能全为零，批量返回 `index` 必须完整且唯一，向量维度一致。成功响应按 `index` 对齐输入，不依赖响应数组顺序。不显示或记录服务错误正文，不自动重试付费 POST。共享 WinHTTP 的证书校验、禁止重定向/自动认证、阶段超时和读循环预算；保存配置只做本地验证，不联网。

查询和索引各使用按需启动的独立有界 worker：每个最多一个在途任务、一个可替换的待处理任务和一个结果槽。查询取消只取消查询；建立索引逐批进行，收到引擎接收回执才请求下一批。关闭面板、修改查询、切换范围、打开配置或退出使旧查询和已经采用的语义结果失效。取消索引、变更 Embedding 配置或退出使索引会话失效，不再提交后续批次。已经完成并被引擎接收的向量保留；在途网络可自行结束，但不能阻塞原文保存和程序退出。

## 存储与检索

sqlite-vec 使用官方 Rust crate 静态链接，固定具体可取得的非 alpha 版本，保留现有 bundled SQLite。SQLite 仍仅由存储 actor 写入。模型计算和网络禁止占用该 actor；候选页只加载必要文本和元数据，不加载 representations BLOB。

向量关联真实条目 ID、输入文本哈希和模型配置 profile。profile 由规范化 API 地址、模型 ID 和输入格式版本生成，不包含密钥、启用状态或索引范围；换密钥、扩大范围不重算已有内容。维度由第一次成功批次确定。不同 profile 或不同维度的向量不得混用；切换模型后普通检索可立即工作，新 profile 通过明确更新索引建立。

输入包含检索所需的标题、别名、标签和文本/路径，但不包含使用次数、固定状态和使用时间。派生输入在截断和哈希前去掉换行、回车、制表符以外的控制字符；原始保存内容保持不变，清理后没有可见正文的剪贴板不索引。重复复制和元数据统计变化不重算；改变参与向量化的内容后旧向量不能代表新内容，下一次明确更新索引补齐。批次接收时再次核对当前条目、范围、profile 和输入哈希；删除、内容改变、配置改变期间返回的旧向量不能复活条目或覆盖新内容。

通过有界分页扫描候选：每页最多检查 128 个已保存条目，输出最多 16 个候选；扫描完成后再检查有界内存待提交条目。未修改输入、profile 匹配的向量不重复请求 API。退出中拒绝新向量变更。重启后无需保存网络任务进度；显式更新通过现有哈希跳过已完成条目并补齐缺失项。

首次建立索引时按实际维度创建 vec0 派生表；关闭功能且没有索引时，不创建派生表或触发空提交。已完成的向量缓存在 actor 内存，待提交向量及元数据合计最多 4 MiB，压力时允许提前提交，先通过剩余预算检查再接收整个批次。新向量未落盘时也能参与本次会话检索。沿用首次脏数据约 55 秒开始提交、健康情况下 60 秒窗口的策略；不能被连续输入无限推迟。配置和收藏仍立即保存；这些现有事务可以一并保存已完成向量。

正常退出保存原文和所有已接收向量，不等待未完成的网络。失败保留缓存，沿用退出重试/取消流程。原文删除和历史清理同步删除关联向量；已清理的条目不能在后续向量批次中重新出现。使用次数、固定状态等变动不重新计算或重写向量坐标。

语义检索使用余弦距离，入库和查询前用 f64 累加归一化向量，再交给 sqlite-vec 的 f32 计算，避免合法但极大/极小坐标导致平方溢出或下溢。词法与语义候选按真实 ID 去重合并，明确的标题/别名/路径匹配保持优先，最终最多 50 条。范围、当前索引范围和删除/内容变更排除在最近邻候选截断前生效，不能先取全库前 50 再过滤造成漏召回。待提交原文覆盖磁盘旧版本，内存向量覆盖相同条目磁盘向量。普通查询不调用网络、不创建表、不提交事务。返回来源依旧是可打开、复制或粘贴的真实条目。

## 验证与交付

使用独立推导的二维/三维向量验证持久化、余弦召回、混合排序、过滤、去重、删除清理、维度/profile 隔离、内存可见性、低频提交和退出重开；用本地 HTTP fixture 验证协议和 native 客户端，不用用户 API Key 或付费服务做测试。并发测试应控制 worker 的开始/完成边界，而非依赖任意睡眠。

运行现有共享测试、fmt、共享和 Windows 目标 Clippy、Windows Release 交叉构建。分别记录普通搜索、向量检索和内存/磁盘负担；随机/人工向量不能证明中文语义效果。当前机器不是 Windows，原生 GUI、DPAPI、WinHTTP 和真实 API 的实机验证需在交付中单独说明。
