# 可选 AI 辅助检索

用户已于 2026-10-03 明确要求实现建议第 1 项，并使用 Claude 格式 API。本次直接执行该已授权范围。

默认关闭。设置中提供 AI 检索配置：启用、API 地址、模型 ID、认证方式（默认 x-api-key，可选 Bearer）、密码输入的 API Key、清除密钥。地址支持 Claude Messages API 的根地址、/v1 或完整 /v1/messages；模型由用户填写。密钥用当前 Windows 用户的 DPAPI 保护，与非敏感配置在同一 SQLite 设置事务内立即保存。

普通搜索保持现有本地查询路径。启用后提供明确的“按意思查找”入口，点击才调用 API；再次点击可取消采用结果。请求只发送本次查询、当前内容范围和已存在功能的 ID/名称/描述，不发送历史正文、文件内容、图片或密钥以外的认证资料。不会在每次输入时调用模型，不新增全局快捷键。

模型仅返回查询计划：最多 6 个短关键词/同义词、可选内容范围、时间枚举（不限、今天、昨天、近 7 天、近 30 天）和最多 3 个真实功能 ID。所有字段与长度验证，未知功能拒绝；不接受模型编造的条目、文件路径、代码或工具执行。计划交给本地检索引擎，合并真实结果并最多显示 50 条。推荐功能只成为可选结果，需要用户自行执行。

时间筛选使用条目首次保存时间；去重历史的再次复制和使用时间不是完整事件记录。文档仍只检索收藏元数据，不新增正文解析或全量向量索引。待提交的内存历史必须参与 AI 改写后的本地查询。

网络由独立、按需启动的 worker 处理，至多一个在途请求加一个待处理请求。取消、编辑查询、改变范围、关闭面板、打开配置或退出使旧结果失效。在途 HTTP 可能仍完成，不能阻塞界面或退出的缓存提交。响应体限制 64 KiB，超时受限；不自动重试收费请求，不将错误响应或密钥写入日志。失败保留本地检索结果。

SQLite 保存窗口、缓存预算、收藏/配置即时保存和退出确认流程不变。AI 计划和回复只在内存中，搜索不产生提交。

Windows 使用 WinHTTP 与 DPAPI，保留小型原生程序。共享协议、查询合并和请求状态能在 macOS 测试；原生网络、加密与界面仅能交叉编译，真实用户 API Key 及 Windows 实机验证在交付说明中明确区分。

## 后续架构评估：功能与私有资料

本节回答用户的后续设计问题，是候选路线，不增加本次实现范围。当前实现仍为查询改写加本地检索，未引入 MCP、向量索引或完整 RAG。

功能应由代码中的能力目录管理：稳定 ID、说明、输入参数、处理器与可调用范围。GUI 搜索、内置 Claude 和外部 Agent 适配层复用同一套目录。AGENTS.md 可作为 Agent 的使用说明与行为约定，并可由目录生成以减少漂移；它不是可执行接口，也不能承担代码层的参数和范围约束。[AGENTS.md 官方定位](https://agents.md/)；[Claude 工具接口](https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview)。

外部 Agent 接入优先评估 MCP：把真实的功能调用作为 Tools，把私有资料的有界检索与读取作为查询接口。Rust 官方 SDK [rmcp](https://github.com/modelcontextprotocol/rust-sdk) 提供协议实现；实际接入应共享正在运行的引擎，包含尚未落盘的内存条目，而不是只读数据库快照。本次仅向模型发送功能目录供推荐，未开放自动执行。

私有资料的原文和元数据仍由 SQLite 管理。全文、拼音、时间和来源检索是索引层；向量检索可补充语义召回。RAG 是“检索片段后交给模型生成回答”的工作流，不是知识库存储格式。如果目标是找到可打开或粘贴的条目，检索到真实来源即可，不必附加一轮生成。

候选语义路线为现有 FTS/拼音与向量召回合并，再根据数据规模评估是否重排。唯一标识、路径、代码、网址应保留词法匹配。长文档按章节/段落切分并保留文件、标题和位置；短剪贴板保持整条。混合召回及片段上下文的思路可参考 [Anthropic Contextual Retrieval](https://www.anthropic.com/engineering/contextual-retrieval)，其文章中的效果数据不能直接当作本工具的验证结果。

向量库候选：[sqlite-vec](https://github.com/asg017/sqlite-vec) 为纯 C、无额外依赖的 SQLite 扩展，支持 Windows 和 Rust 接入，与现有存储路线接近，但项目仍标为 pre-v1，需要固定版本并验证迁移；[LanceDB](https://github.com/lancedb/lancedb) 提供本地全文/向量/SQL检索和 Rust API，适合更大文档集合的备选，尚未测其 Windows 构建、内存和写放大。不直接内嵌完整知识库平台：[RAGFlow](https://github.com/infiniflow/ragflow) 官方当前建议的起步部署为 4 核、16 GB 内存、50 GB 磁盘及 Docker，更适合作为独立服务评估。

低频写入仍是候选路线的约束：历史和派生索引分批提交，内容哈希未改变时不重算；使用统计与固定操作不应重算向量。新内容先走内存词法索引，派生语义索引可以稍后补齐。可以优先对收藏、固定内容和明确选定的文档建立语义索引，再用真实“找不到”的查询评估是否扩展全部历史。

私有数据优先在本地检索。云端重排或生成必须明确发送本次授权的命中片段，检索资料只作为数据，不成为执行指令。[Claude 官方](https://platform.claude.com/docs/en/build-with-claude/embeddings)说明 Anthropic 不提供自己的 embedding 模型；现有 Messages 配置不能自动替代向量化能力，新增时需另配服务或本地 embedding 模型。
