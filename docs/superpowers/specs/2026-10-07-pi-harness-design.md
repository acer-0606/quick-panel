# Pi 工具管家、记忆与反馈设计

用户已选择 Pi，并明确要求由 harness 调用业务接口完成动作，不从自然语言回复猜测操作。沿用当前 Windows 原生工具、原项目目录和开发分支。

## 结果与职责

默认关闭的 AI 管家启用后，使用 Pi Agent Core 1.0.4 的真实 Agent 工具循环。Rust 继续拥有唯一 SQLite actor、来源校验、自动/待确认模式和保存事务。Node 是按需的一次任务后台进程，结束即退出；模型请求通过本地消息桥交给现有 Rust Claude/WinHTTP 传输，凭据不进入 Node 或任何持久化检查点。

Pi 只加载六个业务工具，不加载文件、Shell、浏览器、MCP、编码或自我修改工具。普通 assistant 文本只供解释，提交成果由 organizer_submit 工具及 Rust 的完成校验确定。模型看不到数据库 ID，只使用本轮 index 和来源版本。

## 工具接口

| 名称 | 参数及行为 |
|---|---|
| items_get_context | index；返回本轮来源的 title/kind/alias/tags/context/version，正文摘要仍最多1024字符，无图片/BLOB/文件读取 |
| items_search | query，limit1–8；只搜索本轮及有界整理缓存里的合资格内容元数据，当前范围/排除仍生效，不全库扫描 |
| memory_recall | index，query可空；返回当前来源、用户明确目录规则及全局规则、相关采纳/修改/拒绝负例，最多8条、8192字符 |
| usage_get_summary | index；返回已有 use_count/visits、最近使用时间和反馈聚合，不增加全局行为监控 |
| organizer_submit | index、expected_version、alias(null或48字符)、tags(最多4个，每个24字符)、reason(256字符)；Rust重验并暂存本轮结果，返回结构化错误给Pi修正 |
| memory_propose_rule | index、text(最多512字符)、evidence_ids；只形成待确认记忆规则，不自动变成用户权威偏好 |

所有工具参数拒绝未知字段。提交错误区分可修正的参数问题、已拒绝别名、过期来源和已撤销任务；可修正错误作为真实 tool error 进入下一轮。一个任务必须覆盖本轮全部来源才可完成，结果不由最后一条聊天文本产生。任一来源版本改变即拒绝整轮提交，保存内容与原始执行目标继续保留。

## 状态和预算

- 管家默认关闭；Suggest 默认后台生成建议，Automatic 只填空别名并合并标签。
- 沿用四种范围、间隔30–3600秒（默认60）、每批1–8（默认4）、说明512字符、上下文1024字符。
- Pi最大模型轮次可配置2–8（默认4）；每轮任务工具调用最多32次，累计活动执行时限120秒；一次只有一个真实任务进程。检查点包含elapsed_ms，自动恢复保留全部预算，网络冷却等待不计活动时间，显式用户重试可补充预算。
- IPC协议版本1；每帧最多256KiB，LLM请求最多192KiB、响应64KiB；工具返回最多16KiB，检查点最多128KiB、最多64条消息。字节超限有终态，不继续无界读取。
- 原整理缓存保持256条/2MiB、Ready128条；新增记忆/任务存储独立预算1MiB、记忆最多256条，其中已确认规则最多64条，一份当前检查点及暂存提交。先淘汰较旧普通示例，不静默淘汰已确认规则。
- 自动队列、检查点、AI生成的待确认规则沿用约55秒开始/健康情况下60秒批量事务；人工保存、拒绝/修改反馈、记忆编辑/删除、设置即时提交；正常退出保存已接收缓存。
- 会话不写JSONL文件，Node不写任务日志；同一源码构建后的bundle不动态加载用户目录或配置。
- 崩溃从最近持久化的检查点恢复，最多60秒未落盘进展可重算；已提交结果按来源版本与任务身份去重。不能承诺远程API不重复计费。
- 使用现有5分钟、10分钟、第三次暂停的网络失败退避；参数修正不会消耗该网络失败计数。认证失败（AUTH）或无法启动运行时（RUNTIME_UNAVAILABLE）首次发生即暂停新的自动整理，不消耗网络失败计数；用户修复设置后可明确重试，普通搜索继续可用。
- 预算耗尽或无法完成的单批内容转为可恢复的“需处理”，不反复占据队首，不阻塞其他已排队内容；重试或反馈并重做可将其重新排队。其原因留在管家页面，不弹搜索页错误。
- 取消/配置变更撤销结果；实际运行结束前不释放占用。UI及SQLite actor不做网络或等待子进程，退出不等待模型。

## 记忆和反馈

记忆开启默认true，但父管家仍默认关闭；用户可关闭“记住整理反馈”。回忆优先精确来源和目录范围，再匹配关键词，不新增自动Embedding上传；既有sqlite-vec语义检索和手动建索引流程保留。

人工采用记录来源内成功示例；修改后采用记录真实最终名称；自动应用仅记录AI结果，不作为用户已认可偏好。普通“暂不处理”不推导拒绝原因。新增“反馈并重做”收集拒绝原因，默认仅当前内容；用户可明确选择同目录范围并保存偏好。该操作持久化负例并重排该来源，不重新推荐相同被拒别名。模型提出的跨内容规则在记忆页确认后才能参与权威回忆。

记忆页显示规则与反馈的来源、范围、依据，可编辑/启用/删除；不把单次拒绝升级为全局规则。规则和明确反馈的版本与保存回执对应，失败保留编辑。任务及反馈读取为内存投影，不随绘制、键入或状态刷新写盘。

## 原生和传输

现有OrganizerWork→后台worker改为Pi任务。后台worker持有Node子进程，读LLM请求后复用WinHTTP，读工具请求/检查点后通过有界队列通知UI，UI发actor命令，actor返回带token/call_id的结果再交回worker。每次只允许一个待回复工具；checkpoint合并只保留最新。后台进程全程无窗口；Windows使用子进程生命周期约束，关闭/父进程退出清理拥有的进程。

现有主列表待整理/整理中/有建议标记和保序/预览守卫继续生效。建议页添加反馈入口；管家设置增加记忆和最大轮次，提供Pi启动测试（不调用模型）。API模型、推理强度、密钥、连接测试继续使用现有设置。

## 分发和验证

固定Pi依赖和lockfile，安装不执行第三方生命周期脚本。使用现有Node24.19.0做本机测试；Windows便携包加入经官方SHA256核对的固定Node运行时、Pi bundle、第三方许可。未开启管家时无Node常驻进程。额外运行时会增加下载体积，交付实测体积和本机合成任务启动/峰值数据，明确不代表Windows实机性能。

验证使用真实Pi Agent和工具回合、受控传输fixture、真实Rust actor/SQLite/子进程。覆盖工具错误后修正、记忆召回、反馈幂等、检查点恢复、取消/关闭、范围/版本、所有预算与低写入。无真实API、用户凭据/正文/剪贴板/屏幕读取。Windows原生测试只交叉编译；最终新建ZIP并校验CRC、成员字节与SHA256。
